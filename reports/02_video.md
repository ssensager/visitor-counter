## 1. Что реализовано

`VideoSource` открывает источник через OpenCV, предоставляет метаданные и читает кадры по одному. `VideoProcessor` сбрасывает счётчик при старте генератора, передаёт ему каждый кадр и выдаёт обработанный кадр и новый словарь статистики. `frame_index` начинается с 1. `fps` учитывает время чтения и обработки последних 30 кадров, округляется до одного знака и исключает ожидание потребителя. `progress` вычисляется по метаданным OpenCV и ограничивается единицей. При неизвестном числе кадров значение равно `None`.

Генератор освобождает захват в `finally` при окончании видео, остановке, ошибке или явном закрытии. `encode_jpeg` возвращает байты JPEG с качеством 80 по умолчанию.

Подтверждено освобождение захвата при EOF, остановке после первого кадра, явном закрытии и ошибке счётчика. Проверены неизвестное число кадров и отсутствующий источник.

Отдельные сценарии запускались через `python -B -` со скриптами из PowerShell. Все три проверки завершились с кодом 0.

- **AVI (MJPG) на 60 кадров.** Все 60 JPEG декодировались через `cv2.imdecode`. Входы зафиксированы на кадрах 30 и 60, выход на кадре 55. На последнем кадре `entered=2`, `exited=1`, `current=1`, `progress=1.0` (100%). При заранее выставленном `stop_event` генератор выдал 0 кадров.
- **Ленивое чтение и повторный запуск.** Источник открылся при первом `next()`, который прочитал один кадр с индексом 1. До кадра 55 включительно каждому `next()` соответствовало одно чтение. На кадре 55 значения `entered`, `exited` и `current` составили `1, 1, 0`. При повторном запуске того же `VideoProcessor` первый кадр снова имел индекс 1, а счётчики равнялись 0. При досрочном закрытии каждого генератора `release()` вызван один раз, OpenCV подтвердил закрытие захвата.
- **Пример MJPEG.** Функция `iter_mjpeg` из раздела 6 выдала 8 частей для AVI из 8 кадров. Каждая часть начиналась с границы `--frame` и заголовка `Content-Type: image/jpeg`. Все 8 JPEG декодировались через `cv2.imdecode` в кадры 320×240.

## 5. Проблемы, ограничения и допущения

При первом запуске smoke-теста в песочнице Windows OpenCV не смог открыть `VideoWriter`. При очистке временной папки возникла ошибка `PermissionError: [WinError 5]`. Повторный запуск с доступом к временной папке прошёл. Финальный запуск с `TMPDIR`, указывающей на рабочую папку, также прошёл.

Первый 60-кадровый прогон остановился на кадре 60. Проверочный скрипт ожидал `entered=1`, хотя заглушка добавляет вход каждые 30 кадров. После исправления ожидания на `2` весь прогон прошёл. По результатам проверок дефектов видеомодуля не выявлено.

Открытие URL делегируется OpenCV. Реальная RTSP-камера в проверках не использовалась. Остановка проверяется между вызовами чтения и обработки. Если OpenCV блокируется при чтении, сигнал будет обработан после возврата вызова.

## 6. Что нужно для интеграции

Backend передаёт счётчик, реализующий `VisitorCounterProtocol`, путь к видео и событие остановки задачи. Если потребитель выйдет из цикла досрочно, `closing` сразу закроет генератор и освободит захват. Событие можно установить из обработчика остановки задачи.

```python
from contextlib import closing
from threading import Event

from shared.contracts import VisitorCounterProtocol
from video import VideoProcessor, encode_jpeg


def iter_mjpeg(
    source: str, counter: VisitorCounterProtocol, stop_event: Event
):
    with closing(VideoProcessor(counter).process(source, stop_event)) as frames:
        for frame, stats in frames:
            # Здесь Backend может сохранить stats в состоянии задачи.
            jpeg = encode_jpeg(frame)
            yield b"--frame\r\nContent-Type: image/jpeg\r\n\r\n" + jpeg + b"\r\n"
```
