## 1. Что реализовано

Веб-интерфейс **Visitor Analytics** для подсчёта посетителей в реальном времени спроектирован в чистом типографическом минимализме студийного уровня (Awwwards / Linear aesthetic):

- **Минималистичная дизайн-система без визуального шума:**
  - Полностью исключены эмодзи, декоративные иконки (стрелочки направлений, пиктограммы молнии, силуэты пользователей, камеры).
  - Вся визуальная иерархия выстроена на строгой типографике, выверенных контрастах на глубоком тёмном фоне (`#090a0c`, `#121316`), моноширинных табличных цифрах и тонких границах `rgba(255, 255, 255, 0.07)`.
  - Реализованы 5 ключевых карточек аналитики: «Вошло», «Вышло», «Сейчас внутри (баланс)», «Скорость обработки (FPS)» и «Прогресс видео» с нативным элементом `<progress>`.

- **Интерактивный видеоплеер и виртуальная линия детекции:**
  - Контейнер 16:9 с нативным отображением потока MJPEG (`<img id="stream-image">`).
  - Отрисовка интерактивной виртуальной линии на HiDPI Canvas с использованием Pointer Events API (`pointerdown`, `pointermove`, `pointerup`, `setPointerCapture`) для плавной работы на экранах с мышью, тачем и стилусом.
  - Автоматический расчёт и передача нормализованных координат линии `[[x1, y1], [x2, y2]]` на бэкенд при запуске анализа.

- **Боевая интеграция с REST API и WebSocket:**
  - Демо-режим и синтетическая симуляция пешеходов полностью удалены — интерфейс работает строго с бэкендом.
  - Загрузка видеофайлов (`.mp4`, `.avi`) через Drag-and-Drop или файловый диалог с проверкой расширений и отправкой в `POST /api/video/upload`.
  - Управление жизненным циклом задачи: запуск (`POST /api/video/start/{job_id}`) и остановка (`POST /api/video/stop/{job_id}`).
  - Потоковое обновление метрик через `WS /ws/stats/{job_id}` с автоматическим переключением на fallback polling `GET /api/stats/{job_id}` (каждые 500 мс) при сбоях сокета.
  - Постоянный мониторинг доступности сервера через `GET /api/health` каждые 5 секунд с таймаутами через `AbortSignal.timeout()`.

- **Доступность (A11y) и Modern Web платформенные API:**
  - Нативный HTML `<dialog>` для модальных сообщений с `::backdrop` и дискретной анимацией через `@starting-style`.
  - Контейнерные запросы `@container` для независимости компонентов карточек от размеров окна.
  - Стандартные Baseline-скроллбары `scrollbar-width` и `scrollbar-color`.
  - Скринридер-оповещения через Live Region (`#sr-announcer`), семантические теги `<output>` и учёт медиа-запроса `prefers-reduced-motion`.

## 2. Созданные и изменённые файлы

Все изменения изолированы строго внутри папок `frontend/` и `reports/`:

- `frontend/index.html` — семантическая вёрстка страницы: нативный `<dialog>`, `<progress>`, теги `<output>`, контейнеры карточек и видеоплеера, без внешних CDN и иконочных шрифтов.
- `frontend/css/style.css` — дизайн-система в палитре глубокого обсидиана: CSS-переменные, Container Queries, логические свойства CSS, стилизация нативного скроллбара и состояний доступности.
- `frontend/js/dashboard.js` — модуль визуализации метрик: плавная анимация числовых счётчиков через `requestAnimationFrame`, форматирование чисел и времени через `Intl.NumberFormat` и `Intl.DateTimeFormat`, журнал аудита.
- `frontend/js/video.js` — модуль видеопотока и виртуальной линии: масштабирование холста под `devicePixelRatio`, обработка Pointer Events, расчёт масштабированных координат для инференса.
- `frontend/js/app.js` — центральный координатор приложения: конечный автомат состояний UI (`idle`, `file_selected`, `uploaded`, `processing`, `completed`, `stopped`, `error`), интеграция с REST API, WebSocket и fallback long-polling.
- `reports/04_frontend.md` — чистовой итоговый отчёт модуля (текущий файл).
- `reports/_wip_frontend.md` — промежуточный план и протокол сессии.

## 3. Как запустить и проверить (реальные команды)

### Вариант 1. Интеграционный запуск в составе FastAPI (рекомендуемый боевой режим)
```bash
uvicorn backend.main:app --host 127.0.0.1 --port 8000
```
Открыть в браузере: `http://127.0.0.1:8000/`.

### Вариант 2. Локальный статический сервер (проверка вёрстки и стилей)
```bash
cd C:\Users\yarik\visitor-counter\frontend
python -m http.server 8080
```
Открыть в браузере: `http://127.0.0.1:8080/`.

**Результат проверки:**
- Интерфейс корректно отрисовывается без ошибок в консоли браузера.
- Валидация типов файлов (`.mp4`, `.avi`) блокирует некорректные форматы и выводит доступное сообщение.
- Виртуальная линия контроля на Canvas корректно перетаскивается мышью и тачем; кнопка «По центру» сбрасывает координаты в `0.0, 0.5 -> 1.0, 0.5`.
- При недоступном бэкенде индикатор сервера корректно показывает статус «Сервер: offline».
- При подключении бэкенда индикатор переключается в зелёный цвет «Сервер: online», файл загружается, возвращая `job_id`, и запускается видеопоток с обновлением счётчиков через WebSocket.

## 4. Зависимости и настройки окружения

- **Зависимости сборки:** отсутствуют. Проект реализован на чистом Vanilla JS (ES6+), HTML5 и CSS3 без Node.js, Webpack, Vite, Tailwind или сторонних библиотек.
- **Интеграция с FastAPI:** статические файлы раздаются через `fastapi.staticfiles.StaticFiles`:
  ```python
  app.mount("/", StaticFiles(directory="frontend", html=True), name="frontend")
  ```
- **Браузерные требования:** любой современный браузер Baseline (Chrome 114+, Firefox 115+, Safari 16.4+, Edge 114+).

## 5. Проблемы, ограничения и допущения

- **Таймауты сетевых соединений:** при обработке тяжёлых видеофайлов загрузка через форму может занимать время. Для предотвращения зависания запросов внедрён `AbortSignal.timeout(60000)`.
- **WebSocket Fallback:** в случае нестабильной сети или прокси-серверов, блокирующих сокеты, контроллер автоматически переключается на периодический опрос `GET /api/stats/{job_id}` каждые 500 мс без потери актуальности данных.
- **Отказ от демо-режима:** по прямому требованию синтетический режим симуляции был полностью вырезан, поэтому полноценное воспроизведение детекции требует запущенного бэкенда с моделями YOLOv8/ByteTrack.
