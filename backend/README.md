# Backend Visitor Counter

FastAPI API для одного активного видео. Состояние задач хранится в памяти,
обработка выполняется в отдельном потоке, клиентам передаётся последний JPEG
и актуальная статистика. Рабочая ветка: `feature/backend-api`.

## Запуск (PowerShell, из корня репозитория)

```powershell
python -m venv backend/.venv
backend/.venv/Scripts/python -m pip install -r backend/requirements-dev.txt
$env:VISITOR_USE_MOCK = "1"
backend/.venv/Scripts/python -m uvicorn backend.main:app --host 127.0.0.1 --port 8000 --workers 1
```

Для запуска без тестов достаточно `backend/requirements.txt`.
Открыть `http://127.0.0.1:8000/` или Swagger `http://127.0.0.1:8000/docs`.
Frontend подключается при старте, если есть `frontend/index.html`; иначе `/`
возвращает информационную страницу. После добавления frontend перезапустить сервер.

**Только один процесс / worker**: реестр задач и блокировка не распределены.
Не использовать `--reload` во время обработки: перезапуск теряет состояния задач.

## API

| Метод | URL | Назначение |
|---|---|---|
| GET | `/api/health` | `{"status":"ok"}` |
| POST | `/api/video/upload` | multipart, поле `file`; ответ job_id, filename, status |
| POST | `/api/video/start/{job_id}` | Необязательное тело `{"line":[[0,120],[320,120]]}` |
| POST | `/api/video/stop/{job_id}` | Остановка и ожидание освобождения ресурсов |
| GET | `/api/video/stream/{job_id}` | MJPEG, boundary=frame |
| GET | `/api/stats/{job_id}` | StatsResponse |
| WS | `/ws/stats/{job_id}` | StatsResponse при изменениях, финальный статус и закрытие |

```json
{"job_id":"...","entered":0,"exited":0,"current":0,"fps":0.0,"progress":0.0,"status":"uploaded","error":null}
```

`progress` может быть `null`, если число кадров неизвестно. Баланс `current`
может быть отрицательным, согласно общему контракту `entered - exited`.
Допустимы статусы uploaded, processing, completed, stopped, error.

Примеры для уже запущенного сервера (подставить существующий видеофайл):

```powershell
curl.exe http://127.0.0.1:8000/api/health
curl.exe -F "file=@C:/videos/demo.mp4" http://127.0.0.1:8000/api/video/upload
$jobId = "значение job_id из ответа upload"
Invoke-RestMethod -Method Post "http://127.0.0.1:8000/api/video/start/$jobId" -ContentType "application/json" -Body '{"line":[[0,120],[320,120]]}'
Invoke-RestMethod "http://127.0.0.1:8000/api/stats/$jobId"
Invoke-RestMethod -Method Post "http://127.0.0.1:8000/api/video/stop/$jobId"
```

Браузер использует `<img src="/api/video/stream/JOB_ID">` и
`new WebSocket("ws://127.0.0.1:8000/ws/stats/JOB_ID")`. Подключать MJPEG после
старта; при повторном старте заново подключать оба потока.
Медленные клиенты получают последние значения без очереди всех кадров
(проверка обновлений каждые 50 мс). Отключение клиента не останавливает задачу.

## Ошибки и жизненный цикл

- 415: расширение не `.mp4`/`.avi` (регистр не важен).
- 400: пустой файл; 413: файл больше 512 MiB.
- 404: неизвестная задача.
- 409: уже есть активная задача; остановка uploaded/completed/error;
  MJPEG до старта; остановка занимает больше пяти секунд.
- 422: невалидный JSON/линия (стандартная валидация FastAPI).
- 500: ошибка сохранения/создания потока; 503: сервер завершает работу.
- HTTP-ошибки имеют поле `detail`. Неизвестная WS-задача получает
  `{"detail":"Задача не найдена"}` и закрытие 1008; завершённая задача — 1000.
- Повреждённое видео обнаруживается фоновым декодером: старт принят с 200,
  затем статус `error` и поле `error`; подробности — в серверном журнале.
- Повторный stop для stopped возвращает 200; повторный start сбрасывает
  статистику, кадр и линию, сохраняя job_id и загруженный файл.
- Если stop вернул 409 из-за долгого кадра, сигнал остановки уже установлен;
  опрашивать stats, новую задачу можно запустить после освобождения слота.

## Интеграция с ML/video

`VISITOR_USE_MOCK=1` явно включает `MockVisitorCounter` и локальный простой
OpenCV-reader. Без этой настройки используются экспорты `ml.VisitorCounter`
и `video.VideoProcessor`; если одного из них нет, включается mock с WARNING
в журнале. Ошибки внутренних импортов или инициализации реальных модулей
приводят к статусу error, а не к тихой подмене результатами mock.

Счётчик создаётся один раз на сервис, `reset()` вызывается перед каждым стартом.
`set_line()` получает линию запроса или горизонтальную середину нового видео
(размеры читаются отдельно через OpenCV, чтобы не сохранить линию предыдущего
запуска). `VideoProcessor(counter).process(path, stop_event=event)` должен
возвращать `(frame, stats)` и освобождать ресурсы при окончании/закрытии генератора.
Backend не реализует детекцию, трекинг или подсчёт пересечений.

## Проверки

```powershell
backend/.venv/Scripts/python -m pytest backend/test_backend.py backend/test_live.py -q
```

Тесты используют синтетические MP4/AVI и временные директории, проверяют
контракты, одновременные старты, stop/restart, mock, выбор реальных экспортов
через тестовые классы, WS/MJPEG и живой Uvicorn. Это не замер точности YOLO.

## Ограничения MVP

Нет БД/авторизации и восстановления задач после рестарта. Загруженные файлы
в `storage/uploads/` не удаляются автоматически; очищать их вручную при
остановленном сервере. В памяти остаются метаданные и один последний JPEG
для каждой задачи. Лимит 512 MiB проверяется при копировании уже разобранного
multipart; это не ограничение размера HTTP-запроса на уровне сервера.
Потоки Python нельзя принудительно безопасно завершить: зависший сторонний
декодер/inference потребует перезапуска сервера. При shutdown ждём до 5 секунд.
