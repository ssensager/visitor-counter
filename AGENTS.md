# AGENTS.md — Правила работы AI-агентов в репозитории `visitor-counter`

Этот файл обязателен для всех AI-агентов, работающих над проектом (Antigravity, Cursor, Claude Code, Codex, Copilot и др.).

---

## 1. Первые шаги перед любым кодом

1. Прочитай [`PROJECT_SPEC.md`](./PROJECT_SPEC.md) и [`shared/contracts.py`](./shared/contracts.py).
2. Проверь текущую ветку Git (`git branch --show-current`).
   - Если ты находишься на `main` (и твоя задача — разработка модуля, а не финальная интеграция лидером), **сразу создай или переключись на свою ветку** `feature/<роль>`.
3. Уточни свои разрешённые папки из таблицы в `PROJECT_SPEC.md`.

---

## 2. Железные ограничения (чтобы не сломать работу команды)

- **НЕ меняй и НЕ удаляй файлы в чужих модулях** без явного указания пользователя.
- **НЕ меняй `shared/contracts.py` и `PROJECT_SPEC.md`** самовольно. Если обнаружилась нестыковка в контракте — зафиксируй её в своём отчёте в разделе «Проблемы / предложения по контрактам», но не переписывай интерфейс в одностороннем порядке.
- **НЕ сливай изменения напрямую в `main`.** Вся работа идёт в ветке `feature/<роль>` через Pull Request к руководителю проекта.
- **НЕ добавляй в Git тяжёлые файлы** (веса `.pt`, видеозаписи `.mp4`/`.avi`, папки `venv/`, `.env`).
- **НЕ выдумывай факты.** В отчётах и комментариях указывай только реально написанный код, реально выполненные команды и реальные результаты тестов.

---

## 3. Протокол ведения контекста и отчётности (Скиллы и команды)

В репозитории в `.agents/skills/` настроены 3 рабочих скилла. Они работают и при автоматическом вызове, и по **простым текстовым командам в чате** (или `/skill` в средах, которые это поддерживают):

| Команда в чате | Скилл | Когда вызывать и что делать |
| :--- | :--- | :--- |
| **`план`** | `session-plan` | В начале задачи. Сверить `PROJECT_SPEC.md`, границы папки, создать черновик `reports/_wip_<role>.md` со стартовым планом. |
| **`чекпоинт`** | `session-checkpoint` | После каждого крупного шага, перед паузой или при переполнении контекста. Обновить `reports/_wip_<role>.md`: что сделано, что проверено, какие команды запускались, какие ошибки/блокеры возникли, что делать дальше. |
| **`финал`** | `finalize-report` | Когда модуль готов и протестирован. Проверить `git diff --stat`, убедиться, что чужие файлы не задеты, прогнать тесты и сформировать чистовой отчёт `reports/<nn>_<role>.md` по шаблону `reports/TEMPLATE_REPORT.md` (удалив `_wip_`), подготовить commit и PR. |

**Правило:** даже если пользователь явно не написал слово `чекпоинт`, при завершении крупного этапа обновляй `reports/_wip_<role>.md`, чтобы контекст не потерялся, а финальный отчёт собрался быстро и без пробелов.
