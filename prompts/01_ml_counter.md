```text
Ты выступаешь в роли Senior Computer Vision / ML Engineer в студенческом MVP-проекте «Система подсчёта посетителей на компьютерном зрении» (`visitor-counter`).

### 1. Первые обязательные шаги
1. Изучи `PROJECT_SPEC.md`, `AGENTS.md` и `shared/contracts.py`.
2. Проверь текущую ветку Git (`git branch --show-current`). Если ты на `main`, немедленно переключись на заранее созданную ветку `feature/ml-counter` (`git fetch origin && git checkout feature/ml-counter`). В `main` работать и пушить запрещено.
3. Выполни стартовый протокол `план` (смотри `.agents/skills/session-plan/SKILL.md` и `AGENTS.md`) — запиши план работы в `reports/_wip_ml.md`.

### 2. Твоя зона ответственности и границы
- **Разрешённая папка:** `ml/` (а также временный/итоговый отчёт в `reports/`).
- **НЕ трогай:** `video/`, `backend/`, `frontend/`, `tests/`, `shared/contracts.py`.
- **Ограничения MVP:** НЕ обучай модель с нуля и НЕ собирай обучающий датасет. Используй предобученные веса `YOLOv8n` (`yolov8n.pt`) и встроенный в Ultralytics трекер `ByteTrack`, только класс `person` (COCO class_id `0`). Не пиши код FastAPI или веб-интерфейса.

### 3. Что нужно реализовать в `ml/`
Рекомендуемая структура:
- `ml/__init__.py` (реэкспорт `VisitorCounter`)
- `ml/detector.py` (загрузка `YOLOv8n` один раз при старте, поддержка CUDA если доступна с авто-fallback на CPU, фильтрация только класса `person`)
- `ml/tracker.py` (сопровождение с `ByteTrack`, `persist=True`)
- `ml/counter.py` (виртуальная линия из 2 точек и алгоритм пересечения + защита от дребезга/повторного подсчёта)
- `ml/processor.py` (или единый фасад `VisitorCounter` и CLI-прогон для локальной проверки на видео)

### 4. Жёсткий контракт класса `VisitorCounter`
Класс должен полностью соответствовать `VisitorCounterProtocol` из `shared/contracts.py`:
- `__init__(self, model_path: str | None = None, line: tuple[tuple[int, int], tuple[int, int]] | None = None, conf_threshold: float = 0.35)`
- `set_line(self, p1: tuple[int, int], p2: tuple[int, int]) -> None`
- `process_frame(self, frame: np.ndarray) -> tuple[np.ndarray, dict]`
  - Если `line is None`, при первом кадре автоматически задай горизонтальную линию по центру кадра `((0, h // 2), (w, h // 2))`.
  - Для пересечения используй центр нижней грани bbox (или центр bbox — зафиксируй выбор в отчёте) и знак векторного произведения относительно линии, чтобы определять направление (`entered` / `exited`).
  - Исключай повторный учёт одного `track_id` при колебаниях около линии.
  - На копии кадра рисуй: виртуальную линию, подпись сторон (IN/OUT), bbox'ы людей, их `ID` и мини-счётчик на кадре.
  - Возвращай `(processed_frame, stats)` строго в формате:
    ```python
    {
        "entered": int,
        "exited": int,
        "current": int,  # entered - exited
        "people": [{"id": int, "bbox": [x1, y1, x2, y2]}],
    }
    ```
- `reset(self) -> None` — сбрасывает счётчики и историю треков без повторной загрузки весов модели.

### 5. Самостоятельное тестирование
До завершения работы обязательно проверь:
1. Unit-проверку логики пересечения линии (без тяжёлого видео: имитация движения ID туда-обратно, проверка защиты от дребезга и `reset()`).
2. Независимый прогон скриптом `python -m ml.processor --video <путь>` (или аналогичным локальным тестом) на реальном коротком видео или тестовых кадрах.
3. После каждого значимого шага обновляй `reports/_wip_ml.md` (команда `чекпоинт`).

### 6. Завершение и отчёт
Когда всё готово и проверено, выполни протокол `финал`:
- проверь `git diff --name-only main` (что не задеты чужие модули и не добавлены `.pt` / `.mp4` файлы);
- сформируй чистовой отчёт `reports/01_ml.md` по шаблону `reports/TEMPLATE_REPORT.md` (с указанием нужных зависимостей, инструкцией запуска, результатами проверки и ограничениями);
- подготовь коммит и пуш в ветку `feature/ml-counter` для Pull Request в `main` (в `main` не сливай).
