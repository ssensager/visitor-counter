# Промпт для участника №4 — Frontend Developer (`frontend/`)

Скопируй весь текст ниже (от блока с заданием) и передай своему AI-агенту.

---

```text
Ты выступаешь в роли Frontend Developer & UI/UX Designer в студенческом MVP-проекте «Система подсчёта посетителей на компьютерном зрении» (`visitor-counter`).

### 1. Первые обязательные шаги
1. Изучи `PROJECT_SPEC.md` и `AGENTS.md`.
2. Проверь текущую ветку Git. Если ты на `main`, создай и переключись на ветку `feature/frontend-dashboard`.
3. Выполни стартовый протокол `план` (смотри `.agents/skills/session-plan/SKILL.md` и `AGENTS.md`) — запиши план работы в `reports/_wip_frontend.md`.

### 2. Твоя зона ответственности и границы
- **Разрешённая папка:** `frontend/` (а также временный/итоговый отчёт в `reports/`).
- **НЕ трогай:** `ml/`, `video/`, `backend/`, `tests/`, `shared/contracts.py`.
- **Стек:** чистый `HTML5`, `CSS3`, `JavaScript` (Fetch API, WebSocket, MJPEG `<img>`). Не используй React/Vue/Angular/сборщики без необходимости.
- **Важно:** интерфейс будет раздаваться напрямую из FastAPI по адресу `http://127.0.0.1:8000/`. Все запросы делай строго по **относительным путям** (`/api/...`, `/ws/...`).

### 3. Что нужно реализовать в `frontend/`
Рекомендуемая структура:
- `frontend/index.html`
- `frontend/css/style.css`
- `frontend/js/app.js` (координация состояний и запросов)
- `frontend/js/video.js` (управление видеопотоком MJPEG и отображением линии)
- `frontend/js/dashboard.js` (обновление карточек статистики, статуса и ошибок)

**Дизайн и функционал дашборда «Visitor Analytics»:**
1. **Стиль:** современный минималистичный dashboard (аккуратная типографика, чистые карточки, адаптивная вёрстка, без визуального шума). Должен достойно смотреться на презентации и защите.
2. **Верхняя панель:**
   - название «Visitor Analytics» и подзаголовок;
   - индикатор состояния сервера (опрос `GET /api/health` при загрузке и периодически);
   - статус текущей задачи (`Ожидание`, `Загружено`, `Обработка`, `Остановлено`, `Завершено`, `Ошибка`).
3. **Карточки статистики:**
   - **Вошло** (`entered`)
   - **Вышло** (`exited`)
   - **Сейчас внутри (баланс)** (`current`)
   - дополнительно: **FPS обработки** (`fps`) и **Прогресс** (`progress` в %, если не `null`).
4. **Область просмотра видео:**
   - крупный плеер-контейнер;
   - во время обработки подключается к `<img src="/api/video/stream/{job_id}">`;
   - до запуска или после завершения/ошибки — аккуратное пустое состояние с подсказкой;
   - (опционально, как бонус без перегруза): возможность задать/сбросить координаты виртуальной линии или выбрать дефолтную линию по центру кадра перед стартом (`POST /api/video/start/{job_id}`).
5. **Панель управления видео:**
   - выбор файла (`.mp4`, `.avi`), отображение имени выбранного файла;
   - кнопка «Загрузить видео» -> `POST /api/video/upload`;
   - кнопка «Запустить» -> `POST /api/video/start/{job_id}`;
   - кнопка «Остановить» -> `POST /api/video/stop/{job_id}`;
   - корректная блокировка кнопок по состояниям (нельзя нажать «Старт» до загрузки файла и т.п.) и блок понятных сообщений об ошибках (берётся поле `detail` из ответа API).
6. **Real-time обновления:**
   - подключение к WebSocket (`ws(s)://<host>/ws/stats/{job_id}`) во время обработки (с мягким fallback-опросом `GET /api/stats/{job_id}`, если WS временно отвалился).

### 4. Самостоятельное тестирование
Так как Backend в твоей ветке может ещё отсутствовать:
1. Сделай аккуратный локальный **демо/mock-режим** (активируемый только явным параметром URL `?demo=1`, НЕ по умолчанию!), чтобы ты мог сам открыть `index.html` через локальный Python `http.server` и проверить все состояния UI, анимацию счётчиков и адаптивность.
2. По умолчанию (без `?demo=1`) всё должно работать строго через реальные API-эндпоинты из `PROJECT_SPEC.md`.
3. Проверь отсутствие JS-ошибок в консоли и правильность всех URL-путей и имён JSON-полей (`entered`, `exited`, `current`, `fps`, `progress`, `status`, `error`, `job_id`).
4. Фиксируй этапы командой `чекпоинт` в `reports/_wip_frontend.md`.

### 5. Завершение и отчёт
Когда всё готово и проверено, выполни протокол `финал`:
- проверь `git diff --name-only main` (что изменены только `frontend/` и `reports/`);
- создай отчёт `reports/04_frontend.md` по шаблону `reports/TEMPLATE_REPORT.md` (опиши пути статики, которые должен отдавать FastAPI: `index.html`, `/css/...`, `/js/...`, и как проверить UI в `?demo=1`);
- подготовь коммит и пуш в ветку `feature/frontend-dashboard` для Pull Request в `main` (в `main` не сливай).
```
